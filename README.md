## How to build and run

- Needs Node 18+ and npm. `npm install` once, then `npm run build`.
- Output: `index.html` at the repo root, a single self-contained file (JS and CSS inlined, no network requests). Open it directly in a browser, no server needed; it works offline.
- Source is modular under `src/` (`core`, `blocks`, `games`, `ai`, `ui`, `shell`). Rules modules are pure and run in Node without a browser, so bots and tests can use them directly.
- Test scripts are throwaway and are not committed (see CLAUDE.md); the shared plumbing for them is `tests-helpers.cjs`.

### Planner 16 — Save a snapshot instead of replaying the moves; live dice (discussion, not yet specced)
User asked why a saved game needs a seed and a "replay" when the score, the positions and whose turn it is should be enough. Answer: they are right. The game state is already plain JSON, so a snapshot (options plus the current state) is enough to continue; replay was Claude's design choice (the save is the seed plus the list of moves, rebuilt by playing them again). Replay's costs: resuming re-runs every move, and an old save breaks if a rule is ever changed. A snapshot's cost: when the shape of a game's state changes an old snapshot may not load. **User (later): they are the only player and do not care about saved games, so no old-save support is needed:** the plan is simply a version 3 save `{ version: 3, game, options, state }` with no replay path and no migration; older saves are dropped (the app already drops a save it cannot load). Dice after a resume come from fresh entropy (no random state to store), which makes "live dice" (each roll drawing fresh bits from the browser's secure generator, no pre-set seed) nearly free; the seed stays only for a new game's start so tests that pin a seed keep working. Open: does the user want it queued (Claude's recommendation: yes, one Queue item, before more games are added)?

### Planner 21 — a small wording inconsistency in Pass & Play for Liar's Dice and Treasure Trails (found while building Build Log 59, not fixed)
Those two screens decide "is this seat me?" with `isMe(st.options.seats[...])`, but the game's copy of the seats in `state.options` has no `me` flag (the rules module keeps only name, isBot and preset), so in Pass & Play a first player named "You" is treated as "me": Treasure Trails leaves the name off the prompt ("Use the white sum" instead of "You: Use the white sum"), Liar's Dice says "You open". The right test is `view.seats[i].me` (which Ship, Captain & Crew uses). Cosmetic; nothing else is affected.
